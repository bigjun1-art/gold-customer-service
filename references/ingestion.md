# 资料吸收与知识维护

## 先判断这批资料用于什么

- 课程、文章、培训笔记：提炼方法与适用条件，不转为企业承诺。
- 商品资料、售后政策、活动规则：抽取事实与有效范围，核对版本与来源。
- 正反案例、员工对话：提炼可观察的处理步骤与候选经验；案例结果与作者评价分开。
- 仅供分析、预览或比较的材料：不持久写入，直到用户要求学习或更新。

明确学习任务需要读取的链接可直接读取；单独出现的链接不构成任务。只询问无法从材料确定、且会改变结果的关键事项；其余独立内容继续处理。

## 索引与文件组织

技能根目录下的 `knowledge/index.md` 保存阶段、业务范围目录、方法库链接、来源登记和冲突索引。按实际资料规模拆分，不为每个字段提前生成空文件：

- `knowledge/methods/<topic>.md`：可跨业务使用的方法，不能放店铺专属承诺。
- `knowledge/scopes/<scope>/profile.md`：企业或店铺、渠道、产品范围，以及已确认的匹配条件。
- 同范围下 `rules.md`、`playbooks.md`、`cases.md`：分别保存业务规则、处理手册、去标识案例；有内容时再创建。
- 同范围下 `distillation.md`：用户启动后记录员工经验候选、验证和版本结果。

路径中的 scope 使用稳定的非敏感代号。上下文能唯一确定业务范围时直接复用；无法确定时把资料存为未归属候选，不混入其他范围的生效库。

同批输入不自动证明所有案例属于同一店铺或渠道。只在用户明确关联，或案例自身有可核实标识时绑定。后续“按刚学的回这个顾客”不能替代业务范围核验；范围未明时可完成通用阶段性回复，不在正文引用某店铺的具体补发、赔偿、退换条件。

## 来源记录最小字段

为每个来源分配连续来源 ID，如 S0001：

| 字段 | 内容 |
|---|---|
| 来源 ID / 标题 / 类型 | 原材料标识与类别 |
| 原件定位 | 文件路径与页码、工作表与行、对话轮次，或具体页面链接；不登记带凭据的链接 |
| 内容日期 / 导入日期 | 原文日期未知就注明未知 |
| 范围与版本 | 店铺、渠道、商品、活动、有效期；未知项注明未知 |
| 已处理位置 | 已处理页码、行或对话区间；未完成部分与原因 |
| 去重标识 | 本地文件可用内容哈希；链接内容以版本或可核实内容指纹识别 |
| 处理结果 | 对应知识 ID、候选/已生效/冲突/失效，以及变更位置 |

提炼时只保存能改变以后判断、处理动作或输出质量的内容。聊天流水账、泛泛口号、重复常识不单独入库；有价值的低频例外可以保留，不因出现少而删除。

同一资料重复输入时比对实际内容；无新增就不重复登记、不增加资料数。有新版本时保留先前定位，将被替代条目标为失效并链接新版，不静默抹除旧规则。资料数只统计独立来源，修订版本单列。

## 提炼单位

每项知识都能回答：遇到什么情况、先确认什么、如何判断、接下来做什么、何时不适用、依据在哪里。

业务规则字段：知识 ID、主题、规则内容、适用范围、生效/截止时间、来源 ID 与定位、状态、替代关系。
方法条目字段：知识 ID、触发场景、判断依据、操作步骤、话术例子、反例或例外、升级条件、来源与证据强度。
案例字段：案例 ID、问题背景、关键轮次、处理动作、已知结果、错误或有效点、候选经验、依据。去掉无关身份和订单信息。

证据状态区分：
- 已生效：来源可靠且对当前业务适用；一般方法的已采纳不等于业务效果已验证。
- 候选：来自经验、单案例或未经确认的业务说法，不能直接作为金额与时限承诺。
- 冲突：同一范围存在无法解释的差异；保存双方证据与影响，不凭出现次数决定。
- 失效：被明确替代或超过适用期，保留追踪但不用于当前回复。

业务规则冲突先检查是否是渠道、商品、时间或客户资格不同。用户确认适用版本后只更新相关范围。规则影响现有回复模板或手册时同步修正；旧模板不得继续引用失效条款。

## 分批与验收

长资料分批读取，登记已处理区间；先理解上下文再抽取，不只扫关键词。OCR 模糊、附件缺失和截断内容分别标记，不能声称整份已读完。必要计算用脚本或公式完成。

写入后回读：来源是否能定位、范围是否隔离、条目状态是否一致、引用是否有效、数量是否与实际登记一致。维护只包含必要提炼内容，不存客户姓名、手机号、住址等无关识别信息。不得把凭据或完整聊天归档进技能。

对用户的简短回报包含：这次吸收了什么、形成了哪些可用能力、哪些业务事实尚不能确定、是否还有未处理材料。待确认只列实质问题，不要求每批人工审批；能够确定的部分自行完成。当前阶段保持资料积累，直到用户明确启动员工蒸馏。

## 本地知识更新工具

先解析实际技能根目录。读取命令不修改文件：

```sh
python3 <技能根目录>/scripts/knowledge_store.py read index.md
```

它返回正文和 `sha256`，新文件返回 `missing`。在当前任务工作目录准备完整的新正文，经语义比较确认没有遗漏同一文件的其他有效规则，再写入：

```sh
python3 <技能根目录>/scripts/knowledge_store.py write scopes/store-a/rules.md --content <准备好的正文路径> --expected <该文件刚读取的sha256或missing>
```

每个目标文件必须单独 read，不能把索引的哈希用于规则文件。工具只支持选定知识目录内的非隐藏 Markdown 文件，拒绝路径越界与符号链接；写入使用互斥锁、版本核对、原子替换，旧正文保存在 `.history/`，同内容重复写入无变更。版本变化时先重新读取、合并，不强行覆盖。

多文件更新先写规则与手册、最后更新索引；全部回读后才报告完成。中断时从实际落盘文件和来源 ID 恢复，不能把单文件成功说成整批成功。`.history/` 为历史备份，检索和来源统计均排除该目录。恢复旧版需核对适用性后作为新修订写入，不直接改隐藏备份。

验证脚本只检查写入可靠性，不检查语义、来源真实性或员工经验效果：

```sh
python3 -m unittest discover -s <技能根目录>/tests -p 'test_*.py'
```

运行环境：macOS/Linux 的 Python 3 标准库。无文件锁支持时停止持久写入、保留待写草稿，不退回未经检查的覆盖方式。
