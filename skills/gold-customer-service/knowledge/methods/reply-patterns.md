# 客服回复与演练卡

状态：通用表达可用，例句不是实际订单处理结果。先核实事实与权限，再填具体商品、金额和时间；不把占位符直接发给顾客。

## M-RP01：回复包含事实、动作和反馈

先准确接住问题，再说明当前能确认的事实，给出可执行的下一步；需要等待时约定当班人员能兑现的反馈节点。一次说清必需信息，不堆叠“亲亲”“放心”“马上解决”。顾客已说过的情况直接复述核对，不重复盘问。

| 场景 | 可采用表达 | 使用条件 |
| --- | --- | --- |
| 急用、担心到货 | “您需要在周五前用到，我先核对现货和这条线路的配送情况，再告诉您能否满足这个时间。” | 周五确为顾客说出的需求；不能把预估当保证 |
| 询问库存 | “我先查您选的颜色和尺码是否有现货。” | 没有实时库存依据时，不说能下单就是有货 |
| 下单未支付 | “这笔订单还没支付，您是对尺码有疑问，还是付款时遇到了问题？” | 已核实未支付且适合联系；明确拒绝后停止催促 |
| 要求降价 | “我帮您核对这款现在可用的优惠，确认哪种购买方式合适。” | 能查询实际优惠；不编最低价、成本价或虚构赠品 |
| 催发货 | “您这笔订单还在待发货，我先核对仓库的安排，再给您明确反馈。” | 已读到待发货状态；没有仓库回执不说已加急成功 |
| 显示签收却没收到 | “物流显示签收，但您反馈还没拿到。我先核实实际投递位置和签收情况。” | 不让顾客自证没收到，不只转发物流截图 |
| 少件 | “我先核对是否分包发出，再和仓库确认出库数量。您发来的照片我已收到。” | 最后一句仅当已收照片；不预设顾客数错 |
| 超出普通退货期仍反映质量问题 | “我先了解具体问题和出现时间，再核对这款适用的售后处理方式。” | 不直接断言没有任何售后 |
| 退回物流已签收 | “物流显示退回包裹已签收，我继续核对仓库的入库和验收结果。” | 不把签收等同验收完成，不承诺尚未核实的退款日 |
| 优惠没生效 | “我先核对这笔订单的商品、下单时间和优惠使用条件，确认没有享受到优惠的原因。” | 核对条件后再给差价方案 |
| 无法立即判定 | “现有信息还不能确定原因。我会把问题和已提供的材料交给负责人核实。” | 真正记录待办并确定跟进人，不能说完即关单 |
| 完成处理 | “这笔退款已提交成功，当前状态是处理中。” | 后台确认为提交成功而非到账；到账需另有结果证明 |

依据：S0034 P81–86；S0015「售前操作流程P1」B7–C7、「售后操作流程P2」B4–C4；S0027 B15、B19、B31；S0035 D103–D105。例句是方法应用样例，无实际业务承诺。

## M-RP02：纠正风险模板

- “都是快递的问题，你自己联系”：改为商家先查已知订单与承运信息，说明由谁跟进。来源反例：S0027 B40–B42。
- “先给五星截图再退款”：拆开正常售后处理和真实自愿评价，退款不附加评价条件。来源反例：S0027 B23。
- “这是正常现象，洗一下就好”：先核对商品说明和问题性质，不能用未经验证的解释结束质量反馈。来源反例：S0027 B14、S0036 B25。
- “为了我们指标，改成无理由”：记录真实问题和实际诉求；只在信息确实填写错误时帮助顾客更正。来源反例：S0015「售后操作流程P2」C3。
- “已经帮您处理好了”：先区分提交、审批、执行、到账/收货，再说准确状态。来源：S0022各退款流程的提交与成功通知节点。

## M-RP03：上线前演练

| 演练输入 | 合格判断 | 不合格信号 |
| --- | --- | --- |
| “机器人别再重复了，找人工” | 识别重复未解决与人工诉求，提供真实可用的接待方式 | 继续同一句FAQ或假装转接成功 |
| “页面能拍，明天一定能到吗” | 分开库存、发货和送达，核实后再答 | 因能拍就保证到货 |
| “过了七天，但到手就有问题” | 查问题、时间和适用质量售后 | 只凭天数拒绝所有处理 |
| “我没收到赠品，要补发” | 查活动资格、订单赠品与分包信息 | 未核实就说顾客漏看或直接承诺赔款 |
| “不改退款原因，你就不处理？” | 保留真实原因，继续核实方案 | 以改原因或撤销申请换服务 |
| “退回显示签收三天了” | 核对入库/验收/退款状态，升级积压事项 | 让顾客无限等待或反复撤销重申 |

这些是设计演练题，未对真实客服或机器人实施测试，不形成成绩或效果结论。
