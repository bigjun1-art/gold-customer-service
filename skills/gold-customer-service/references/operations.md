# 客服运营、反馈优先级与训练

## 客服主管复盘

先确认统计范围：店铺/渠道、时间区间、时区、案件单位、工作时间定义、数据完整性。沿用用户已有定义；缺失时给出本次临时分析口径，不将其保存为公司考核规则。

将反馈按问题类型、业务影响、重复程度和已知处理结果归类。区分同一案件反复发消息与多个独立客户遇到同一问题，分别统计会话数、工单数、独立案件数。一个案件可有多个问题标签，但总案件数不可按标签重复累加。

优先级以证据解释，不凭愤怒词数量或客户消费额决定：
- 优先处理：正在持续造成实际损失、影响范围较广、临近明确业务截止时间、处理卡在权限或系统环节。
- 尽快改进：多个独立案例重复发生、重复咨询明显、知识或流程缺口影响处理。
- 持续观察：个别建议、尚未验证的趋势、信息不足的反馈。

客户价值、续约和流失风险在相关业务有可靠数据时可作排序因素，不影响基础服务权益。不要移植外部项目的 ARR 倍数、关键词倍数或补偿额度。数据支持时再量化；每个优先项保留案例、影响、判断依据与建议动作。

复盘产物：主要问题 → 根因证据 → 影响范围 → 具体改进项 → 所需责任角色 → 验收办法。责任人、完成期限未确定时标待分配，不声称已派单。没有排期授权，不创建定时任务或主动发送周报。

## 指标口径

| 指标 | 计算与必要条件 |
|---|---|
| CSAT 满意率 | 满意有效回答数 / 有效回答数；先确定量表和满意阈值，同时报告回收数、邀请数或可得响应率 |
| NPS | 采用 0–10 分推荐意愿题时，9–10 分占比减0–6分占比；不把普通好评分数直接映射 |
| CES 客户费力度 | 保留原问卷题目、量表和高低分方向，按该问卷定义汇总，不跨量表直接平均 |
| 首次响应时间 | 客户发起至首次有效人工/机器人响应的间隔，两者分开；注明是否工作时间，自动回执不默认算有效响应 |
| 首次联系解决率 | 有足够结果与观察窗口证据、在首次联系解决且未因同问题重开案件数 / 合格可评价案件数；另列排除与未知数 |
| 解决时长 | 案件开始至可确认解决时间；注明暂停、重开如何计入；未解决案件另报当前等待时长 |
| 平均处理时长 | 需要实际工作时段记录；不能用整场聊天首尾间隔代替客服实际工作时长 |
| 重复咨询率 | 在明确窗口内就同一问题再次咨询的案件数 / 可观察案件数；用户身份或窗口不足则无法确定 |
| SLA 达成率 | 在适用且已确定的时限内满足目标的案件数 / 到期可评价案件数；未配置时限不能称违规或达标 |

数值0与缺失值分别处理，不能用真假判断将0分钟工作时间替换成自然时间。响应人身份不能仅以“不是顾客本人”判断为人工客服，还应区分机器人、系统消息和协作人。

人数与比例使用代码或公式复算。报告样本、缺失、观察窗口、均值/中位数等所用口径；不编行业基准，不把未满观察窗口的案件当成功。不同渠道、难度、权限和排班应分层比较，未经授权不生成个人绩效结论。

## 升级分工与交接

可按一线、专员、主管建立处理层级，但实际角色、权限、时限来自用户业务资料。只有一般框架时将额度和时限留为待配置。

升级条件从事实出发：超出权限、必要资料冲突、同案反复失败、需要专业判断或跨部门处理。顾客要求主管应被明确回应；关键词只能提示核查，不能单凭“投诉”判定极高风险。对外承诺频率和响应时间须有排班/服务标准依据。

交接清单：活动案件、紧急事项、等顾客/等内部事项、已采取动作、下一步与责任角色、期限依据、证据定位。排除已确认解决和重复案件；敏感原话只保留必要摘要。

## FAQ、培训与演练

FAQ 从高频问题、难点和失败案例建立，标题用顾客常用问法，合并同义问法；答案先直接回答，再列条件与操作，链接到同范围的业务依据和详细手册。没有依据的答案留候选。

培训围绕“识别信号—判断依据—处理动作—表达—升级”设计：
1. 取一个去标识案例，给学员看足够背景，暂不展示优秀回复。
2. 学员给判断和回复；按统一质检维度反馈。
3. 展示正例、反例和区别，指出一项最值得改进的动作。
4. 使用变化条件的新案例再练，确认学到判断方法而非背句子。

情景演练的模拟结果与真实业务效果分开保存。员工对话的匿名培训用途不自动升级为个人蒸馏或员工排行。

## 跨文件一致性验收

规则或手册修改后，核对 FAQ 与回复是否使用同一有效条件、手册升级条件是否与实际权限一致、SLA 是否能由数据中的时间字段计算。按影响范围选择一般咨询、投诉或异常交接案例走完整路径；无需每次全量重测。找到断点时修对应环节，不只润色表述。
